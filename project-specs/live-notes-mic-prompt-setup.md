## 2. Goals and non-goals
- Goal: a live, scrolling transcript-and-notes pane in the main window for the whole recording.
- Goal: a Notion-style floating "In a meeting?" card with Record / Not now / snooze that replaces the OS notification and the in-window banner as the detection surface.
- Delivery order: REQ-1 (must) first, then REQ-2 (should). REQ-1 is independently shippable. REQ-2 ships whole or not at all (its toggle defaults on, so a half-built card would regress detection feedback); if REQ-2 slips, the branch still certifies on REQ-1 and REQ-2 is reported unsatisfied.
- Non-goal: showing speaker names or diarization live (the live transcript has `speaker: null`).
- Non-goal: editing transcript text live.
- Non-goal: a separate pop-out notes window.
- Non-goal: changing the call-detection ladder, `SAME_APP_REMINDER_SECS`, or `any_mic_app` semantics; only gating what the user sees.
- Non-goal: queueing multiple simultaneous detections (see AC-2.6).
- Non-goal: any network call, telemetry, or cloud model use.
- Non-goal: tray/menu-bar menu changes (no snooze or ignored-apps entries there) and CLI changes (`minutes record`, detection parity); both keep current behavior.
- Non-goal: keyboard-only or VoiceOver operation of the floating card this round. The card is mouse-driven like the existing recording pill; users who need an accessible path turn the card off (AC-2.12), which restores the OS notification, or start recording from the main window.
- Non-goal: the main window's hide-to-tray-on-close behavior. No task touches it; it is not re-asserted here.
- Non-goal: recording-pill Stop latency. Todd's mid-run report ("Hitting stop recording on the small overlay feature does not respond very fast") was fixed directly in commit 5c35f245 (the pill closes as soon as `cmd_stop_recording` returns); it is not part of this spec.
- Non-goal: virtualizing the live pane. Rows are capped instead (AC-1.11).
- Non-goal: preserving pane state across an app relaunch mid-recording. On relaunch the pane starts with both cursors at 0 and reloads everything from the files (AC-1.13); nothing is persisted.
- Non-goal: coordinating with other readers of `live-transcript.jsonl` (CLI `minutes live`, MCP server, Coach). The pane opens the file read-only, takes no lock, and tolerates a torn final line (AC-1.2, AC-1.1 cursor rule); no writer-side change.
- Accessibility position (personal fork, accepted trade): the card is mouse-only and its toggle defaults on; the live pane gets the minimal criteria in AC-1.12. No further accessibility work this round.

## 3. Requirements

Identifiers used below: `app_name` is the display name detection produces (e.g. "Microsoft Teams", "Slack", "Google Chrome"); it is the key for every suppression rule in REQ-2. `process_name` is carried through unchanged for the existing recording path but is not a suppression key.

### REQ-1: Live transcript and notes pane while recording
**Statement**: While a recording is active, the main window's recording view shall show every live transcript line and every user note as they arrive, so the whole meeting is visible before processing.
**Serves**: "cannot see what is being captured" / success measure "transcript growing live with notes inline".
**Context**: the live transcript engine writes `~/.minutes/live-transcript.jsonl` during recordings (one JSON object per line: `line`, `ts`, `offset_ms`, `duration_ms`, `text`, `speaker`). Notes are appended by `cmd_add_note` (`commands.rs:7145` → `notes::add_note`, `notes.rs:176-205`) to `~/.minutes/current-notes.md` as `[M:SS] text`, where `M:SS` is elapsed recording time with paused time excluded. The UI today polls `cmd_live_transcript_status` (`index.html` ~8560-8640) and clears `#live-bar` when a recording starts. `cmd_capture_status` already reports `recording`, `paused`, `processing`, `elapsed`.
**Mechanism (binding)**: one new Tauri command `cmd_live_view(after_line: u64, after_note: u64)` in `commands.rs`, backed by `minutes_core::live_view::read_since(after_line, after_note) -> LiveView { lines: Vec<{line, offset_ms, text}>, total_lines, notes: Vec<{note, offset_ms, text}>, total_notes }` in a new file `crates/core/src/live_view.rs`. Numbering and cursors: a transcript item's `line` is the `line` field inside the JSON object (not its file position); the pane's line cursor is the highest `line` value it has rendered, so a torn or malformed line that is skipped this poll and completed by the next poll is still picked up. A note's `note` is its physical 1-based line index in `current-notes.md`; skipped lines consume a number and `total_notes` is the physical line count. `add_note` writes exactly one physical line per note (`notes.rs:205`, text trimmed), so continuation lines do not occur from the app; any such line is skipped. A note's `offset_ms` is parsed from its `[M:SS]` prefix; `?:??` yields `offset_ms = null`, and `read_since` resolves it server-side to the `offset_ms` of the nearest preceding note (lower `note` number) that has a real offset, else 0, so the value depends only on file content, never on poll boundaries. The pane polls this command every 1000 ms while `cmd_capture_status.recording` is true.
**Acceptance**:
- AC-1.1: WHEN `read_since(after_line, after_note)` is called THE SYSTEM SHALL return only transcript lines with `line > after_line` and only notes with `note > after_note`, plus the current totals. (Unit test: fixture files with 3 lines / 2 notes, cursors 0 and 2.)
- AC-1.2: WHEN `live-transcript.jsonl` or `current-notes.md` is missing or unreadable THE SYSTEM SHALL return zero items and total 0 for that source without error. WHEN a transcript line is not valid JSON or lacks `line`/`text`, or a note line lacks the `[M:SS]` prefix, THE SYSTEM SHALL skip it and continue. (Unit tests for each.)
- AC-1.3: WHEN a recording is active AND a poll returns new items THE SYSTEM SHALL insert them into a scrolling pane in the recording view, transcript lines as `M:SS` (from `offset_ms`) plus `text`, notes with a leading "Note" label and a 3px left border in the UI accent color. Rows are ordered by `offset_ms` ascending; ties keep arrival order (stable sort). (Evidence: unit test that `read_since` resolves a `?:??` note to its predecessor's offset, including when the predecessor was returned by an earlier cursor; Playwright with a stubbed `invoke` returning scripted `cmd_live_view` pages: assert the poll period is 1000 ms via a stub clock, assert DOM rows appear within 200 ms of the stubbed promise resolving, and assert ordering for a page containing a resolved note between two transcript lines. Real end-to-end latency on the Mac is release blocker RB-1.)
- AC-1.4: WHEN a poll returns `total_lines` smaller than the pane's line cursor OR `total_notes` smaller than its note cursor (file rotated, new recording) THE SYSTEM SHALL reset both cursors to 0 and clear the pane before appending. (Evidence: Playwright, stubbed page sequence with a shrinking `total_lines`.)
- AC-1.5: WHEN new rows are appended AND the pane is scrolled to within 24px of its bottom THE SYSTEM SHALL scroll so the newest row is visible; WHEN the user has scrolled further up THE SYSTEM SHALL keep their scroll position and show a "Jump to latest" control that scrolls to the bottom when clicked and hides once at the bottom. (Evidence: Playwright, scroll the container up, append a page, assert scrollTop unchanged and control visible; click, assert at bottom and control hidden.)
- AC-1.6: WHEN `cmd_capture_status.paused` becomes true THE SYSTEM SHALL insert a "Paused" marker row at the end of the pane; WHEN it becomes false THE SYSTEM SHALL continue appending after that marker. Repeated pauses produce repeated markers. (Evidence: Playwright, stubbed `cmd_capture_status` toggling `paused` twice; assert two marker rows.)
- AC-1.7: WHEN a recording is active AND the pane has no rows THE SYSTEM SHALL show the current `diagnostic` text from `cmd_live_transcript_status` (or "Waiting for speech…" when that is empty) in place of the empty list. (Evidence: Playwright, stubbed empty page plus stubbed diagnostic string; assert text.)
- AC-1.8: WHEN `cmd_capture_status.recording` turns false THE SYSTEM SHALL stop polling, keep all rows visible, and show a header "Recording stopped · processing…" while `cmd_capture_status.processing` is true. WHEN `processing` turns false THE SYSTEM SHALL hide the pane and return the recording view to its idle state as today. WHEN the user navigates to another view before that THE SYSTEM SHALL hide the pane. WHEN a new recording starts THE SYSTEM SHALL clear the pane, reset cursors, and show it. (Evidence: Playwright, stubbed status sequence recording→stopped+processing→idle, then recording again; assert header text, pane hidden, then pane visible and empty.)
- AC-1.9: WHEN the pane is visible AND the main window viewport is 460x520 (its minimum, `main.rs:349`) THE SYSTEM SHALL keep the recording bar controls (Coach, Add Note, Stop Recording) fully within the viewport without page scrolling; the pane scrolls internally. (Evidence: Playwright at a 460x520 viewport asserting each control's bounding box lies inside the viewport and `document.scrollingElement.scrollHeight <= clientHeight`, plus a screenshot for the report.)
- AC-1.10: WHEN the UI locale is zh-CN or pt-BR THE SYSTEM SHALL translate the new strings ("Note", "Paused", "Jump to latest", "Waiting for speech…", "Recording stopped · processing…") through `window.MinutesI18n.t`, with keys added to both `tauri/src/locales/*.js`. (Evidence: grep that each key exists in both locale files.)
- AC-1.11: WHEN the pane holds more than 2000 rows THE SYSTEM SHALL remove the oldest rows from the DOM until 2000 remain; cursors are unaffected (they track `line`/`note` numbers, not DOM rows). (Evidence: Playwright with a stubbed page of 2100 lines.) Reasoned against a 3-hour meeting at one line per 30 s plus notes, which stays under the cap.
- AC-1.12: WHEN the pane is rendered THE SYSTEM SHALL mark the list container `role="log"` (implicitly `aria-live="polite"`), make it keyboard-scrollable (`tabindex="0"`), and use an accent border color with at least 3:1 contrast against the pane background in both color schemes. (Evidence: Playwright DOM assertions plus a computed-contrast check run twice with `page.emulateMedia({ colorScheme })` set to light and dark.)
- AC-1.13: WHEN the app is relaunched while a recording is active THE SYSTEM SHALL start the pane with both cursors at 0 on the first poll and render every existing line and note. (Evidence: the AC-1.1 cursor-0 unit test plus the AC-1.8 start-clears Playwright case; no separate runtime test.)
**Priority**: must

### REQ-2: Notion-style meeting-detected prompt card with snooze
**Statement**: When call detection fires and no recording is active, the system shall show a floating always-on-top card at the top-right of the screen offering Record, Not now, and snooze, replacing the OS notification and the in-window banner.
**Serves**: "record? nudge is a notification plus banner" / success measure "floating card within a second, snoozed apps stop nagging".
**Context**: detection lives in `tauri/src-tauri/src/call_detect.rs` (emits `call:detected {app_name, process_name, is_reminder}` at ~633 and posts `show_user_notification` at ~617; emits `call:ended {app_name, process_name, countdown_secs}` at ~753). The banner is `#call-detected-banner` in `index.html` ~5934 with a listener at ~15771 that also calls `cmd_show_main_window`. Reference windows: `recording-hud` (`commands.rs:20589-20668`, flag set and `content_protected`) and `meeting-prompt` (`main.rs:1364-1450`, token-staged payload drained by `cmd_get_meeting_prompt`). Calendar overlap: `minutes_core::calendar::events_overlapping(now)`.
**Mechanism (binding)**:
- New core module `crates/core/src/call_prompt.rs`: `SnoozeLedger` persisted at `~/.minutes/call-prompt-snooze.json` (0600, atomic write via temp+rename, same pattern as `recording-pause.json`) mapping `app_name → until_rfc3339`; `fn decide(app_name, now, ignored_apps: &[String], ledger: &SnoozeLedger, this_call: &HashSet<String>) -> Decision { Suppressed(reason) | Prompt }`.
- New config key `call_detection.prompt_card: bool` (default true) and `call_detection.ignored_apps: Vec<String>` (default empty), documented in `docs/architecture/config.md`.
- New window label `meeting-detected`, page `tauri/src/meeting-detected.html`, fixed size 360x156 logical px (entry added to the per-label size table at `main.rs:477` and to `skip_initial_state` at `main.rs:2071` so no window state is persisted), created by `show_meeting_detected_card(app, payload) -> Result<(), String>` in `commands.rs` using the `recording-hud` flag set (`decorations(false)`, `transparent(true)`, `shadow(false)`, `always_on_top(true)`, `focused(false)`, `focusable(false)`, `skip_taskbar(true)`, `content_protected(config.privacy.hide_from_screen_share)`); payload staged by token like `meeting-prompt`.
- Pure surface chooser in `commands.rs`: `fn call_prompt_surface(prompt_card_on: bool, card_result: Option<Result<(), String>>) -> Surface { Card | Notification }`.
- New Tauri commands: `cmd_get_meeting_detected(token) -> CardPayload` (drains the staged payload), `cmd_close_meeting_detected()` (closes the window if open), `cmd_meeting_detected_choice(choice: "record" | "not_now" | "snooze_call" | "snooze_hour" | "never")` (applies AC-2.7 to AC-2.9), all registered in `main.rs`.
- `AppState` gains `call_prompt: Mutex<CallPromptState { this_call: HashSet<String>, card_open: bool }>`. `this_call` is cleared per `app_name` on `call:ended` and is empty on app start. `card_open` is set when the window is created and cleared from the window `Destroyed` event handler for label `meeting-detected` (main.rs `on_window_event`), which fires for every close path including OS close and webview crash.
**Acceptance**:
- AC-2.1: WHEN `decide` is called THE SYSTEM SHALL return, in this order and stopping at the first match: `Suppressed(Ignored)` if `app_name` is in `ignored_apps`; `Suppressed(Snoozed)` if the ledger has an entry for `app_name` with `until > now`; `Suppressed(ThisCall)` if `app_name` is in `this_call`; otherwise `Prompt`. (Unit tests: one per branch plus the fall-through.)
- AC-2.2: WHEN the ledger file is missing or is not valid JSON THE SYSTEM SHALL treat it as empty. WHEN the ledger is loaded THE SYSTEM SHALL ignore entries with `until <= now` (no file write on read). WHEN a snooze is added THE SYSTEM SHALL write the file with expired entries dropped, mode 0600. (Unit tests: missing file, corrupt file, expired entry ignored on read, expired entry absent after a write.)
- AC-2.3: WHEN `call:detected` fires with `is_reminder = false` AND no recording is active AND `prompt_card` is on AND `decide` returns `Prompt` THE SYSTEM SHALL create the `meeting-detected` window immediately, before any calendar lookup, showing: heading "In a meeting?", `app_name`, and buttons Record, Not now, and a snooze control. The card SHALL NOT post the OS notification and SHALL NOT bring the main window to the front. Mechanism: `fn prepare_card(app_name, process_name, calendar: impl FnOnce() -> Vec<CalendarEvent> + Send + 'static) -> (CardPayload, Receiver<Option<String>>)` in `commands.rs` builds the payload synchronously and spawns the calendar closure on a thread; the window is created from the payload before the receiver is read. (Evidence: unit test that `prepare_card` returns in under 100 ms when the closure sleeps 3 s, proving the lookup is not awaited; `call_prompt_surface` unit test; code-reviewer inspection of the window builder for the flag set and `content_protected`. Detect-to-visible latency under 1 s on the Mac is release blocker RB-1.)
- AC-2.4: WHEN the card is created THE SYSTEM SHALL position it 16px from the top and right edges of the work area of the monitor containing the current cursor (`cursor_position()` + `monitor_from_point`), falling back to the primary monitor when no monitor contains the cursor. Mechanism: pure `fn top_right_in(work_area: (x, y, w, h), card: (w, h), inset: i32) -> (x, y)` in `commands.rs`. (Evidence: unit tests for `top_right_in` on a primary and a secondary monitor with non-zero origin; the monitor selection call is inspection-only, added to section 5(d).) `get_top_right_position` (`main.rs:1452-1466`) is not reused or modified.
- AC-2.5: WHEN the card is shown THE SYSTEM SHALL run `calendar::events_overlapping(now)` (returns `Vec<CalendarEvent>`, `calendar.rs:291`) on the thread spawned by `prepare_card` and wait on its receiver with a 1500 ms budget; WHEN the Vec is non-empty within the budget AND the card is still open THE SYSTEM SHALL emit `meeting-detected:calendar {title}` with the title of the event with the earliest start (first in Vec order on a tie) and the card SHALL show it under the app name; WHEN the budget elapses or the Vec is empty THE SYSTEM SHALL show no title row; a panic in the closure is treated as empty. (Unit tests: closure sleeping 3 s → `None`; two overlapping events → earliest-start title; empty → `None`.)
- AC-2.6: WHEN a card is already open AND any `call:detected` fires (same or different `app_name`, reminder or not) THE SYSTEM SHALL ignore it (no replacement, no queue, no notification). WHEN the card closes, the next non-reminder detection that passes `decide` prompts normally. (Unit test on the AppState "card open" guard.)
- AC-2.7: WHEN Record is clicked THE SYSTEM SHALL invoke the existing `cmd_start_recording` with `source: "call_detect"` (intent Call; no title argument, calendar title still applied at processing time as today); WHEN it resolves THE SYSTEM SHALL close the card; WHEN it rejects THE SYSTEM SHALL keep the card open, replace the button row with the text "Couldn't start recording" plus the error, and close as Not now (AC-2.8) after 5000 ms. (Evidence: Playwright with a stubbed `invoke` that rejects.)
- AC-2.8: WHEN Not now is clicked OR the auto-dismiss timer elapses THE SYSTEM SHALL close the card and add `app_name` to the "this call" set. The timer is 20000 ms, overridable by the page URL query `dismiss_ms` for tests. WHEN `call:ended` fires for that `app_name` THE SYSTEM SHALL remove it from the set. (Evidence: Playwright with `dismiss_ms=500` asserting the close invoke; unit test for set add/remove on the AppState helper.)
- AC-2.9: WHEN the snooze control is opened THE SYSTEM SHALL offer exactly three items: "Not for this call" (behaves as AC-2.8), "1 hour" (writes `app_name → now + 60 min` to the ledger, then closes the card), "Never for <app_name>" (appends `app_name` to `call_detection.ignored_apps`, saves the config, then closes the card). (Evidence: Playwright asserting the menu has exactly the three items and each fires the matching `cmd_meeting_detected_choice`; unit tests on the choice handler for the ledger write and the config append.)
- AC-2.10: WHEN Minutes restarts inside a "1 hour" window THE SYSTEM SHALL still suppress that app until the stored `until`; WHEN Minutes restarts THE SYSTEM SHALL forget all "this call" suppressions. (Evidence: unit test that builds a `CallPromptState`, adds a this-call entry and a ledger snooze, drops the state, constructs a fresh one and reloads the ledger from the same temp file, then asserts `decide` returns `Suppressed(Snoozed)` for the snoozed app and `Prompt` for the this-call app.)
- AC-2.11: WHEN a recording starts by any other means while the card is open THE SYSTEM SHALL close the card (the page polls `cmd_capture_status` every 1000 ms like `recording-hud.html` and closes itself when `recording` is true). WHEN `call_detection.prompt_card` is turned off in Settings while a card is open THE SYSTEM SHALL close the card immediately (the settings handler invokes `cmd_close_meeting_detected`). (Evidence: Playwright on the card with a stubbed status flipping `recording` to true, assert the close invoke; Playwright on the settings toggle, assert `cmd_close_meeting_detected` is invoked when turning off.)
- AC-2.12: WHEN `call_detection.prompt_card` is off AND no recording is active THE SYSTEM SHALL behave as today minus the banner: for `is_reminder = false` post the existing "<app> call detected" OS notification, and for `is_reminder = true` post the existing "Recording is still off" notification, both only when `decide` returns `Prompt`. WHEN `prompt_card` is on AND `is_reminder = true` THE SYSTEM SHALL do nothing (no card, no notification). WHEN `prompt_card` is on AND creating the card window returns `Err` THE SYSTEM SHALL post the "<app> call detected" OS notification instead. (Unit tests on `call_prompt_surface`: on+Ok → Card; on+Err → Notification; off → Notification.)
- AC-2.13: WHEN the app starts THE SYSTEM SHALL no longer contain the `#call-detected-banner` markup, its `call:detected` listener, or the `cmd_show_main_window` call from that listener in `index.html`; the `#call-ended-banner` and its listeners are unchanged. (Evidence: grep in the diff plus `cargo build -p minutes-app`.)
- AC-2.14: WHEN the user opens Settings > Call detection THE SYSTEM SHALL show a toggle "Ask with a floating prompt" bound to `call_detection.prompt_card`, and an "Ignored apps" list with one row per entry in `call_detection.ignored_apps` and a remove control per row. WHEN a row is removed THE SYSTEM SHALL save the config without that app, and that app SHALL prompt again on its next non-reminder detection (AC-2.1 fall-through). (Evidence: Playwright on the settings markup with stubbed `cmd_get_settings`/`cmd_set_setting`; the config round-trip is a `config.rs` unit test.)
- AC-2.15: WHEN the UI locale is zh-CN or pt-BR THE SYSTEM SHALL translate the card strings ("In a meeting?", "Record", "Not now", "Snooze", "Not for this call", "1 hour", "Never for {app}") and the settings strings ("Ask with a floating prompt", "Ignored apps", "Remove") through `window.MinutesI18n.t`, with keys added to both `tauri/src/locales/*.js`. (Evidence: grep that each key exists in both locale files.)
- AC-2.16: WHEN the `meeting-detected` window is destroyed by any means (a choice, auto-dismiss, external recording start, toggle off, OS close, webview crash) THE SYSTEM SHALL clear `card_open` so the next qualifying detection prompts. (Evidence: unit test on `CallPromptState::card_closed()`; code-reviewer inspection that the `Destroyed` handler in `main.rs` calls it for this label.)
- AC-2.17: WHEN the branch diff is reviewed THE SYSTEM SHALL contain no new network client usage: no added `ureq`, `reqwest`, `hyper`, `TcpStream`, `fetch(`, `XMLHttpRequest`, `WebSocket`, or `navigator.sendBeacon` in the diff. (Evidence: `git diff feat/notion-parity...HEAD | grep -E '^\+.*(ureq|reqwest|hyper|TcpStream|fetch\(|XMLHttpRequest|WebSocket|sendBeacon)'` returns nothing.)

## 5. Constraints
- Stack: Rust workspace (`crates/core` = `minutes-core`, `tauri/src-tauri` = `minutes-app`), Tauri v2, frontend is plain HTML/JS with no bundler or framework; i18n via `window.MinutesI18n.t` with English strings as keys.
- Toolchain: Homebrew rust (repo pin ignored). Run `cargo clippy --all --no-default-features -- -D warnings -A clippy::chunks_exact_to_as_chunks`, `cargo fmt --all -- --check`, `cargo test -p minutes-core --no-default-features`, `cargo test -p minutes-app --bin minutes-app`.
- Desktop app has no tracing subscriber; `tracing::info!` is not logged. Use the existing `show_user_notification`/events for anything user-visible.
- Never replace `/Applications/Minutes.app`. Dev install only via `MINUTES_DEV_SIGNING_IDENTITY="Apple Development: Todd Stoel (CC2G5TPS8Q)" ./scripts/install-dev-app.sh`, and never while `~/.minutes/recording.pid` exists.
- Privacy: no network calls added; the new window passes `content_protected(config.privacy.hide_from_screen_share)`; the snooze ledger is 0600.
- Minimal diff: reuse the `recording-hud` window flag set and the `meeting-prompt` payload/token pattern as references; do not refactor adjacent code. Where a reference conflicts with an AC, the AC wins (AC-2.4).
- Accepted evidence under this pipeline (supersedes the CLAUDE.md click-test rule for the automated gates, because the user is recording on this machine): (a) `cargo test` output for every unit test named after an AC id; (b) for HTML behaviour, a Playwright script run against the page on `file://` with a stub `window.__TAURI__` that scripts `invoke`/`listen` responses and a stub clock where an AC names one, with screenshots attached; (c) `cargo build -p minutes-app` succeeding; (d) code-reviewer inspection of the window-builder call for the flag set and `content_protected` (AC-2.3) and a diff grep for removed markup (AC-2.13).
